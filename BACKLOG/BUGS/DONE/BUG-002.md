# BUG-002: optimize-images.mjs — images manquantes passent silencieusement

**Type:** Bug
**Statut:** A faire
**Priorite:** Moyenne
**Complexite:** XS
**Tags:** build, images
**Depends on:** none
**Blocked by:** —
**Date creation:** 2026-03-28

---

## Description

`generateManifest(results)` recoit le tableau brut `results` qui peut contenir des entrees `null` (images source non trouvees). La fonction fait un `.filter(Boolean)` en interne donc le manifest genere est correct, mais si des images sont introuvables le build reussit silencieusement avec un manifest incomplet.

Pas de warning, pas d'erreur. Le probleme ne serait decouvert qu'en voyant des images manquantes sur le site.

## Cause racine

Ligne 344 : `generateManifest(results)` au lieu de `generateManifest(processed)`, et absence de validation du nombre d'images traitees vs le catalogue.

## Fichiers concernes
- `scripts/optimize-images.mjs` — script prebuild d'optimisation d'images

## Approche recommandee

1. Passer `processed` a `generateManifest` au lieu de `results` (coherence)
2. Ajouter un warning si `processed.length < IMAGE_CATALOG.length` avec la liste des images manquantes
3. Ne PAS faire de `process.exit(1)` — le guard existant (ligne 342) qui preserve le manifest est un comportement voulu pour le dev local sans images sources

## Criteres d'acceptation
- [ ] `generateManifest` recoit `processed` (pas `results`)
- [ ] Un warning console liste les images manquantes si `processed.length < IMAGE_CATALOG.length`
- [ ] Le guard "No images processed, keeping existing manifest" reste en place
- [ ] `pnpm build` passe sans erreur

## Tests de validation
- [ ] Renommer temporairement une image source, lancer `pnpm images:optimize` — un warning doit lister l'image manquante
- [ ] Remettre l'image, relancer — aucun warning
