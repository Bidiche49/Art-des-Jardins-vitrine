# BUG-004: generateFavicon() écrase les vrais favicons à chaque build

**Type:** Bug
**Statut:** A faire
**Priorite:** Haute
**Complexite:** XS
**Tags:** favicon, build, regression
**Depends on:** none
**Blocked by:** —
**Date creation:** 2026-03-28

---

## Description

La fonction `generateFavicon()` dans `scripts/optimize-images.mjs` (lignes 164-196) génère des favicons à partir d'un SVG codé en dur qui dessine une feuille verte générique. Elle est appelée à chaque `pnpm build` via le prebuild `images:optimize`, écrasant systématiquement les vrais favicons (logo Art des Jardins).

C'est la vraie cause racine du BUG-001 : même après restauration manuelle des bons fichiers, le prochain build les écrase.

### Cause racine

`generateFavicon()` :
1. Crée un SVG avec un dégradé vert générique (`#22c55e` → `#15803d`)
2. Le convertit en `favicon.ico` (32x32 PNG, pas un vrai ICO multi-résolution)
3. Le convertit en `apple-touch-icon.png` (180x180)
4. Écrase `favicon.svg` avec ce SVG générique

Les vrais favicons (générés à partir du logo) sont dans `icon-32.png`, `icon-192.png`, `icon-512.png` etc. et ne sont PAS touchés par cette fonction.

## Fichiers concernes
- `scripts/optimize-images.mjs` — supprimer `generateFavicon()` et son appel dans `main()`

## Approche recommandee

**Supprimer** `generateFavicon()` entièrement + son appel dans `main()` + la ligne summary "3 favicon files generated". Les favicons sont des assets statiques qui ne changent jamais, pas besoin de les régénérer à chaque build.

Supprimer aussi `favicon.svg` de `public/` s'il existe (c'est le SVG générique, pas le vrai logo).

## Criteres d'acceptation
- [ ] `generateFavicon()` supprimée de `scripts/optimize-images.mjs`
- [ ] L'appel `await generateFavicon()` supprimé de `main()`
- [ ] La ligne summary favicon supprimée
- [ ] `pnpm images:optimize` ne touche plus `favicon.ico`, `apple-touch-icon.png`, `favicon.svg`
- [ ] `public/favicon.svg` supprimé (SVG générique orphelin)
