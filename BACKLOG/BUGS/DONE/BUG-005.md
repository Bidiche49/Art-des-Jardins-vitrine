# BUG-005: Schema.org addressLocality utilise la ville cible au lieu de l'adresse reelle

**Type:** Bug
**Statut:** A faire
**Priorite:** Haute
**Complexite:** XS
**Tags:** seo, schema, structured-data
**Depends on:** none
**Blocked by:** —
**Date creation:** 2026-03-28

---

## Description

Le composant `LocalBusinessCitySchema.tsx` genere un JSON-LD `LocalBusiness` avec `address.addressLocality` defini sur la ville cible (ex: "Avrille") alors que l'entreprise est physiquement aux Ponts-de-Ce. Cela cree une incoherence avec la fiche Google Business Profile et constitue un signal de manipulation locale.

## Cause racine

Le composant recoit `city` en prop et l'utilise pour `addressLocality` (ligne 32). L'adresse physique devrait toujours pointer vers le siege social, et la ville cible devrait etre uniquement dans `areaServed`.

## Approche recommandee

1. **`address`** : toujours utiliser l'adresse reelle du siege (Les Ponts-de-Ce, 49130) depuis `SITE.address`
2. **`areaServed`** : garder la ville cible (le service est bien propose dans cette ville)
3. **Ajouter `makesOffer`** (optionnel, bonus SEO) pour decrire le service propose dans cette ville :
   ```json
   "makesOffer": {
     "@type": "Offer",
     "itemOffered": {
       "@type": "Service",
       "name": "Elagage a Avrille",
       "areaServed": { "@type": "City", "name": "Avrille" }
     }
   }
   ```
