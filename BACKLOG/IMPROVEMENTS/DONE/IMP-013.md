# IMP-013: Refactorer le data model cities-data.ts pour contenu service x ville

**Type:** Improvement
**Statut:** A faire
**Priorite:** Critique
**Complexite:** M
**Tags:** seo, data-architecture, cities
**Depends on:** none
**Blocked by:** —
**Date creation:** 2026-03-28

---

## Description

Actuellement `cities-data.ts` stocke un `specificContent: string` par ville, identique quel que soit le service. Cela signifie que `/paysagiste-avrille/` et `/elagage-avrille/` affichent le meme contenu principal, ce qui cree de la duplication interne et un signal doorway pour Google.

Le data model doit etre refactore pour supporter du contenu unique par couple service x ville.

## Cause racine

L'interface `CityData` n'a qu'un seul champ `specificContent` au lieu d'un contenu par service. Le template `[serviceCity]/page.tsx` injecte ce contenu identique pour les 4 services d'une meme ville.

## Approche recommandee

1. **Ajouter une interface `ServiceCityContent`** :
   ```typescript
   interface ServiceCityContent {
     content: string;           // 3-5 paragraphes uniques pour ce service dans cette ville
     metaDescription: string;   // meta description unique (150-160 chars)
     highlights?: string[];     // points forts specifiques a ce service dans cette ville (remplace le features grid generique)
   }
   ```

2. **Ajouter un champ `serviceContent` a `CityData`** :
   ```typescript
   serviceContent: Partial<Record<'paysagiste' | 'elagage' | 'entretien-jardin' | 'abattage', ServiceCityContent>>;
   ```
   `Partial` pour permettre un rollout progressif — si un service n'a pas de contenu specifique, fallback sur `specificContent` existant.

3. **Conserver `specificContent` comme fallback** — pas de breaking change. Le template utilisera `serviceContent[service] ?? specificContent`.

4. **Ajouter `metaDescriptionTemplate` fallback** dans `ServiceCityData` — le template actuel continue de fonctionner si `serviceContent` n'a pas de `metaDescription`.

5. **Creer un fichier exemple** avec le contenu pour 1 ville (Avrille) x 4 services, pour valider la structure avant le remplissage massif (IMP-014).

## Fichiers concernes

- `src/lib/cities-data.ts` — refactoring des interfaces + ajout du champ `serviceContent` + contenu exemple Avrille
- `src/app/[serviceCity]/page.tsx` — adapter `generateMetadata` et le rendu pour lire `serviceContent` avec fallback
