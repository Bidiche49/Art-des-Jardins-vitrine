## Description

Les images OG (`/images/og-*.jpg`) sont servies avec `cache-control: public, max-age=31536000, immutable` (1 an, immuable). Combiné aux noms de fichiers fixes (sans hash), chaque modification d'OG nécessite une purge manuelle Cloudflare, sinon le CDN sert l'ancienne version pendant 1 an.

Symptôme observé : après mise à jour des OG, le CDN a continué de servir les vieilles versions jusqu'à purge manuelle.

**Cause** : le header est défini dans `next.config.js:35` (mode Docker) pour `/images/(.*)`. En mode export statique, c'est probablement Cloudflare lui-même qui applique ce header via une règle. À vérifier en début de ticket.

Deux solutions possibles :
- **A** : retirer `immutable` et baisser `max-age` à ~1h pour les `og-*.jpg` spécifiquement (assets sensibles aux modifs), garder le long cache pour le reste
- **B** : versionner les noms de fichier (`og-image-v2.jpg`) et adapter `layout.tsx` + autres pages utilisant les OG

## Fichiers concernes

- `next.config.js` — ligne 35, header cache-control sur `/images/(.*)`
- `src/app/layout.tsx` — référence `og-image.jpg` (ligne 74, 85)
- Autres pages avec metadata OG (à scanner) : services, paysagiste-angers, etc.
- Cloudflare dashboard — vérifier les Page Rules / Transform Rules / Cache Rules sur ce domaine

## Notes

- Headers Cloudflare actuels (constatés) :
  ```
  cache-control: public, max-age=31536000, immutable
  cf-cache-status: HIT
  age: jusqu'à 37 jours observés
  ```
- Compromis : un cache court sur OG impact léger sur le coût CDN (quelques fetches par jour vers l'origine), mais évite les purges manuelles à chaque modif.
- Penser à appliquer le même raisonnement aux autres images sensibles aux modifs (logo, favicon) si elles ont aussi `immutable`.
