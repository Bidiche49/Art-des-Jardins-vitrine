## Description

Les 4 pages /services/{slug}/ (paysagisme, entretien-jardin, elagage, abattage) ont un ton commercial incompatible avec le standard pose par les pages Angers v2. Le contenu peut rester generique (role different des pages locales), mais le ton et les formulations doivent s aligner.

## Problemes identifies

1. **Formulations sauce AI** — "Pret a demarrer votre projet ?", "Nos equipes executent les travaux avec soin", "Notre equipe vous repond sous 48h"
2. **Benefits interchangeables** — "Valorisation de votre propriete", "Espace de detente personnalise" (n importe quel concurrent peut ecrire ca)
3. **Ton commercial** — usage excessif de "nous/notre", registre affirmatif-engageant au lieu de declaratif-factuel
4. **Process** — descriptions generiques sans element concret
5. **FAQ** — reponses generiques sans ancrage

## Scope

Fichier template : src/app/services/[slug]/page.tsx
Fichier donnees : src/lib/services-data.ts (descriptions, benefits, process, faq)

Les 4 services principaux + les services secondaires si presents (terrasse, cloture, etc.)

## Criteres d acceptation
- [ ] Zero formulation de la liste interdite du cahier copywriting
- [ ] Benefits specifiques et non interchangeables
- [ ] Ton declaratif, factuel, sobre — coherent avec les pages Angers v2
- [ ] CTA sobres, pas de promesse
- [ ] FAQ avec au moins un element concret par reponse
- [ ] pnpm build sans erreur

## Tests de validation
- [ ] pnpm build
- [ ] Comparaison tonale avec elagage-angers (reference de ton)
- [ ] Test concurrent sur chaque benefit et phrase de process

## Notes
A planifier en Wave 3 ou 4, AVANT le merge de copywriting-v2 dans main. Les 72 pages service x ville linkent toutes vers /services/{slug}/ — le ton doit etre aligne au moment du merge.
